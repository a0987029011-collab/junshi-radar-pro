# 軍師雷達系統架構

## 設計原則

1. **人工審核優先**：模型只縮小範圍，不取代使用者畫線與最終決策。
2. **研究訊號與正式策略分離**：00632R 穿越與站回關鍵價位不可自動升級。
3. **策略設定與程式分離**：權重、門檻、分類、成熟度與報告時間讀取同一份 JSON。
4. **資料來源可替換**：歷史、即時與籌碼供應商不影響掃描與 UI。
5. **可重現**：每次掃描保存策略版本、資料時間、輸入摘要與結果。

## 模組

| 模組 | 位置 | 責任 |
|---|---|---|
| 策略設定 | `config/strategy.json` | 所有策略與風控參數 |
| 資料介面 | `lib/data-adapter.ts` | 隔離 mock、CSV、盤後與即時資料 |
| 掃描引擎 | `lib/scanner-engine.ts` | Swing high、下降趨勢線、突破、縮柱支撐 |
| 評分引擎 | `lib/scoring-engine.ts` | 100 + 20 分、分類與成熟度 |
| 回測引擎 | `lib/backtest-engine.ts` | 00632R 正規化穿越與事件後統計 |
| 風控計算 | `lib/risk-calculator.ts` | 股數、手續費、證交稅、停損與 R/R |
| Web App | `app/`、`components/` | 排行、圖表、審核、持股與策略 |
| API | `app/api/radar/route.ts` | 提供掃描結果給未來 App／通知服務 |

## 掃描流程

```text
1. 建立全市場股票母體
2. 排除股本 < 20 億、日均量 < 1,000 張
3. 將日線重採樣為週線、月線
4. 計算 MACD、DPO、成交量與籌碼衍生欄位
5. 找 swing high 並擬合下降趨勢線
6. 判斷開盤／盤中／收盤突破
7. 尋找縮柱支撐、關鍵價位與首次健康回測
8. 計算 100 分、結構 20 分與成熟度
9. 依 S / A / A+ / Seed / 觀察分類
10. 輸出理由、缺件與人工審核清單
```

## 資料模型（下一階段）

- `instruments`：代號、市場、產業、股本、上市櫃與下市日期
- `bars`：symbol、timeframe、timestamp、OHLCV、調整因子
- `chips`：法人、融資融券、借券、集中度與資料日期
- `scan_runs`：策略版本、資料截點、執行狀態
- `scan_results`：分數、分類、成熟度、理由、缺件與各訊號
- `reviews`：使用者通過／觀察／排除及備註
- `positions`：進場、股數、停損、目標與交易成本
- `backtest_runs`：樣本範圍、事件定義、績效與資料品質

## 掃描時程

- 06:00：早報使用前一交易日完整資料
- 盤中：即時事件流持續判斷開盤、最高價與最新價是否穿越趨勢線
- 12:00：盤中量價與突破摘要
- 13:55：尾盤／收盤確認清單
- 21:30：等待法人、融資融券與借券資料完整後重新評分

真正上線時，排程與網站分離成背景工作者；網站只讀最近成功完成的結果。任何資料源延遲都必須標記，不可沿用舊籌碼卻顯示為今日資料。

## 安全與可靠性

- API 金鑰只存託管環境變數。
- 即時供應商斷線時顯示資料延遲，不以 mock 補成真實資料。
- 所有自動分類保留原始訊號與策略版本，方便事後追溯。
- 回測排除未來函數，納入下市股票、交易成本與流動性條件。
- 正式交易前仍由使用者人工審核，不串自動下單。
